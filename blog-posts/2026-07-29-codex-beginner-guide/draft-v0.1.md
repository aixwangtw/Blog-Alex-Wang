faqs:
  - question: Codex 要付費才能用嗎？額度到底怎麼算？
    answer: 這是留言區最大宗的焦慮，有人問「不是要高級會員才能用嗎」，有人買了商務版說「一下午就被我用光」，也有人直接說「比較在意的是錢，希望列出完成影片上的工作會耗多少錢」。影片的說法是有免費版，有 ChatGPT 帳號就能用。額度沒有公定換算表，同一個任務花多少受模型、上下文長度、任務複雜度影響，OpenAI 也會不定期調整方案內容。務實的做法是先用免費版跑幾個小任務，開著 Codex 使用量頁面（chatgpt.com/codex/settings/usage）看消耗速度，心裡有底了再決定要不要升級。
  - question: Codex、Claude Code、Antigravity 一堆同類工具，到底選哪個？
    answer: 留言區被拿出來比較的名字包括 Codex、Claude Code、Antigravity、OpenCode、OpenClaw 和 Google 的 agent，全片讚數最高的提問（16 讚）就是在問 Claude 20x 方案和「Claude 5x 加 Codex」怎麼選，Gary 本人的回覆是預算有限又需要大量開發時，Claude 加 Codex 的組合 CP 值很高。更簡單的判準是先看你已經在付錢的訂閱：有 ChatGPT 帳號，Codex 免費版就是零成本的起點；已訂 Claude，就先把 Claude Code 用熟。這類工具的基本功（專案、權限、上下文、規則文件）相通，學會一個換工具的成本很低，不用卡在選擇這關。至於 Antigravity 2.0 的差異我還沒實際用過，不裝懂。
  - question: 讓 AI 直接動我的電腦，資安沒問題嗎？怎麼確認它不會越權？
    answer: 「怎麼確認 AI agent 不會越權」「檔案有機敏性嗎」「不可控的風險太大了」這類留言反覆出現，是採用門檻裡最硬的一塊。Codex 的防線是影片講的兩層：專案資料夾決定它看得到哪裡，權限模式決定它能不能不問就動手。務實做法是機敏檔案不要放進工作資料夾，新手停留在要求核准或代我核准模式讓危險動作都先過你這關，AGENTS.md 寫明「不要刪除原始檔」這類禁令。有留言者提出用 VM 隔離跑，對高敏感場景是合理的加固。但要誠實說，只要給了完整存取權，防線就只剩自然語言規則，這也是影片不建議新手開 YOLO 模式的原因。
  - question: 沒有桌機，iPad 能用嗎？蘋果系統會不會被擋？
    answer: 兩則留言分別問了 iPad 和「蘋果系統是不是會被擋」。後者可以放心，影片全程就是在 Mac 上示範，桌面版本來就有 Mac 版。iPad 那邊答案沒這麼好：桌面 app 裝不上 iPad，瀏覽器裡的雲端版或許開得起來，但「直接操作你本機檔案」這個核心能力在 iPad 上是沒有的。想要影片裡的完整體驗，還是需要一台電腦。
  - question: 公司禁止使用非企業版 AI，是不是就不能用了？
    answer: 是，公司規範優先，別拿公司資料冒險，這沒有繞路的空間。能做的事有兩件：問 IT 或主管有沒有導入企業方案的規劃，這類需求越多人提公司越有動力處理；以及先在自己的私人電腦、私人專案上把工具練熟，等公司哪天開放，你是那個已經會用的人。
  - question: 影片裡說「複製貼上開一個新的 session」，到底複製什麼？

  - question: 我是特教老師／退休人士／設計工作者，這跟我的工作有什麼關係？

標題卡上給 Codex 下的定義只有一行：一個會在你電腦裡幹活的 AI Agent。這章接下來所有的比較，都是在拆「在你電腦裡」跟「幹活」這兩件事。

### 一個完全不寫程式的同事，問了最有代表性的問題

Gary 說他們團隊有一個運營夥伴，完全不寫程式。前陣子他讓這位夥伴開始用 Codex，對方問的第一個問題是：

> 這不就是一個放在桌面上的 ChatGPT 嗎？

Gary 回他，兩個其實差很多。

用 ChatGPT 的流程長這樣：你得先把檔案丟上去，它改完，你還要自己下載、自己整理。做事的還是你自己，AI 只負責中間那一小段。

Codex 的流程不同。它直接鑽進你的電腦，幫你讀檔案、改檔案、做表格、做簡報，甚至幫你架一個網站。Gary 在影片裡的原話是：「它不是一個聊天視窗，它是一個會在你電腦裡幹活的 agent。」

<img src="/images/blog/codex-beginner-guide/shot_0036s.jpg" alt="投影片左右對照：左欄紅字 ChatGPT 列出「你先把檔案丟上去、它改完、你自己下載整理、做事的還是你」，右欄綠字 Codex 列出「鑽進你的電腦、讀檔案改檔案、做表格做簡報、甚至幫你架網站」，中間是一個 VS 圓形圖示">

影片把這組對照直接排成左右兩欄。左邊 ChatGPT 四點，右邊 Codex 四點，中間一個 VS。這張圖如果只能記一句，記右欄第一行：鑽進你的電腦。

### 買了特斯拉，只拿來聽廣播

<img src="/images/blog/codex-beginner-guide/shot_0047s.jpg" alt="汽車駕駛座內部畫面，中控螢幕上方飄著幾個音符，中央打上白色大字「大材小用」並加了一條橘色底線">

Gary 的比喻是：把 Codex 當 ChatGPT 用，有點像買了一台特斯拉，結果只拿來聽廣播。畫面直接切到車內的中控台，中間打上「大材小用」四個字，上頭還飄著音符。

比喻還有後半段。正因為它碰得到你的檔案，你就不能像用聊天機器人那樣，丟一句話就走人。Gary 的說法是，一個能動你整台電腦的東西，你得先學會怎麼駕馭它。

影片沒有一上來就教操作，先花時間講規則，原因就在這裡。

### 影片會走過的四段路

<img src="/images/blog/codex-beginner-guide/shot_0072s.jpg" alt="影片大綱投影片，標題「這支影片」，下方橫排四個帶圖示的區塊：Codex 是什麼（與 ChatGPT / Claude Code 的差異）、四個基本功（專案 / 權限 / 上下文 / AGENTS）、實際應用（本地文件 / Skill / 外掛 / 自動化）、發揮最大價值（不只執行，還能教你）">

Gary 在開場把整支影片的路線攤開，投影片上是四個並排的區塊：

- Codex 是什麼，以及它跟 ChatGPT、Claude Code 的差異
- 四個基本功：專案、權限、上下文、AGENTS markdown 文件
- 實際應用：本地文件操作、Skills、外掛程式、自動化
- 發揮最大價值：不只讓它執行任務，還能讓它教你

四個基本功那一段，Gary 說他會用一個生活化的例子帶著看。第四段的重點是怎麼讓 Codex 在幫你執行任務之外，多做一件事。

### 現在的 AI 工具，可以先分成兩種

分類本身很簡單。

第一種是大多數人最熟的網頁版 chatbot，像 ChatGPT、Claude 網頁版。它住在瀏覽器裡，你問它答。就像前面那個故事講的，上傳下載、整理收尾，動手的還是你自己，因為它根本碰不到你的電腦。

第二種就是 Codex 這種住在你電腦裡的 agent。你把一個工作環境交給它，它就能在你授權的範圍內，自己讀文件、改文件、執行工具、產生成品，不用你一直上傳下載、複製貼上。

<img src="/images/blog/codex-beginner-guide/shot_0102s.jpg" alt="投影片左右對照：左欄灰字「網頁 chatbot」列出住在瀏覽器裡、你問它答、碰不到你的電腦、上傳下載你自己來；右欄橘字「電腦裡的 agent」列出給它一個工作環境、自己讀檔改檔執行、直接產出成品、不用一直複製貼上，中間是 VS 圖示">

Gary 說這就是它跟 ChatGPT 最根本的差別：一個在線上回答你，一個直接在你電腦裡替你做事。

右欄那句「在你授權的範圍內」值得先圈起來。授權範圍怎麼給，就是後面權限那一段要處理的事。

### 住在電腦裡的 agent，又分桌面 App 跟終端機

<img src="/images/blog/codex-beginner-guide/shot_0120s.jpg" alt="投影片兩張卡片並排：左邊橘框「桌面 App」畫著有紅黃綠三顆按鈕的視窗、標示圖形介面，右上角掛著橘色「今天聊這個」標籤；右邊「CLI 終端機」是黑底終端機畫面，顯示 $ codex 指令與游標，下方註明工程師常用">

這種住在電腦裡的 agent，還可以再往下分兩種。

一種是桌面 App，有圖形介面，就是一般人熟悉的視窗操作。另一種是終端機版本，畫面黑黑的、一行一行打指令，又叫 CLI，Gary 說比較多工程師在用。

影片標明今天只聊桌面 App，理由是它對非技術的人最友善。投影片右上角那顆「今天聊這個」的橘色標籤，就掛在桌面 App 那一格。後面所有的操作示範，都是桌面版的介面。

### Codex 和 Claude Code 是同一個道理

<img src="/images/blog/codex-beginner-guide/shot_0131s.jpg" alt="桌面 App 與 CLI 終端機對照投影片，下方加上兩組品牌對應：OpenAI 標誌加箭頭指向 Codex、Anthropic 標誌加箭頭指向 Claude Code，底下一行字寫著「同一個道理，兩家各自的 AI Agent」">

你可能也聽過 Claude Code、Claude Cowork。Gary 說它們跟 Codex 是同一個道理，就是 OpenAI 跟 Anthropic 兩大巨頭各自的 AI Agent。投影片下方把兩邊的 logo 對排：OpenAI 指向 Codex，Anthropic 指向 Claude Code。

對讀者的實際意義是，這篇後面講的觀念（工作環境、權限、上下文）不會只綁在 Codex 上。哪天換另一家的 agent，骨架大致相通。

### 門檻：有 ChatGPT 帳號就能開始

<img src="/images/blog/codex-beginner-guide/shot_0138s.jpg" alt="黑底畫面中央一枚橢圓形徽章，橘色勾勾圖示後面寫著「免費版・零門檻」">

如果你已經用過 Claude Code，只是想單純試試 Codex，Gary 說很適合，因為它有免費版，只要有 ChatGPT 帳號就能用。畫面上打了一枚「免費版・零門檻」的徽章。

至於 Claude 的 App 版本跟 Codex 的 App 版本差在哪，Gary 給的是個人感受：他覺得 Codex 在使用體驗上做得比 Claude 順手很多，從使用額度的角度看，他的形容是「更是便宜大碗」。影片這段沒有列方案價格，也沒有列額度數字，就當作一個用過的人的偏好參考，實際貴不貴還是要自己開來跑跑看。
## 介面導覽（影片 2:27）

進到介面之前，Gary 先用一張卡把前面的理由收攏：免費版零門檻、體驗更順手、額度划算。他的原話是「Codex 更是便宜大碗」。

<img src="/images/blog/codex-beginner-guide/shot_0147s.jpg" alt="投影片卡片由上到下列出免費版・零門檻、體驗更順手、額度划算三項，畫面下方字幕寫著 Codex 更是便宜大碗">

然後他打開 Codex 桌面版，從版面開始帶。以下每一段都對得到影片畫面，你可以邊看邊在自己的 Codex 上點。

### 三欄式版面：左邊管對話、中間下指令、右邊看結果

Gary 說 Codex 是很直觀的三欄式設計：左邊管對話和專案，中間是輸入指令，右邊看結果和預覽。

剛裝好、什麼都還沒開的狀態長這樣。中間只有一句「我們該做什麼？」加一個輸入框，右邊是空的，只列出「瀏覽器 ⌘T」和「終端」兩個入口等你叫用。

<img src="/images/blog/codex-beginner-guide/shot_0156s.jpg" alt="Codex 桌面版空白狀態的三欄視窗，中間顯示「我們該做什麼？」與輸入框，右欄用橘色標籤標示「右欄：結果・預覽」，只列出瀏覽器與終端兩個入口">

左欄由上往下是新聊天、搜尋、外掛程式、自動化、專案，視窗最底下是設定。再下面的「聊天」區塊放歷史對話，全新安裝時會顯示「沒有對話」。

<img src="/images/blog/codex-beginner-guide/shot_0159s.jpg" alt="Codex 左欄被橘色外框圈起來，欄內依序是新聊天、搜尋、外掛程式、自動化、專案，底部為設定，右側說明卡列出對話紀錄、任務、專案、外掛・設定">

### 開新對話有兩種開法，決定 Codex 讀不讀得到你的檔案

這是整段介面導覽裡最該記住的地方。Gary 把開新對話分成兩種情境：

- 只是問普通問題，直接按左上角的新聊天就好。
- 某個專案裡的任務，要**從專案資料夾旁邊開新對話**。

差別在上下文。Gary 說走專案那條路，Codex 才會讀到正確的資料夾、拿到正確的上下文，包含 AGENTS markdown 和你提前整理好的專案背景。他在這裡補了一句「細節我等等會講」，AGENTS markdown 是後面獨立一段的主題。

實際操作是從左欄「專案」那一列進去，Codex 會叫出 macOS 的檔案選擇器讓你挑資料夾。

<img src="/images/blog/codex-beginner-guide/shot_0166s.jpg" alt="Codex 視窗上浮出 macOS 檔案選擇器，畫面右側說明卡寫著從專案資料夾開新對話，並列出 Codex 才讀到正確資料夾、拿到正確上下文、含 AGENTS.md 三點">

影片裡挑的是「Codex_demo 素材」底下的「講座籌備_demo」資料夾，選好之後按右下角的打開。

<img src="/images/blog/codex-beginner-guide/shot_0169s.jpg" alt="macOS 檔案選擇器停在 Codex_demo 素材路徑，清單中選取名為 講座籌備_demo 的資料夾，右下角是取消與打開按鈕">

### 中欄：打字或語音，Gary 有八成時間用講的

中間就是你跟 Codex 溝通的地方，用起來跟 ChatGPT 差不多，可以直接打字，也可以用語音輸入。輸入框下方那排小圖示由左到右分別是加號（附加）、核准模式的下拉選單（影片裡設在「請求核准」）、模型選擇（畫面上是 5.5 超高）、麥克風，以及右邊的送出箭頭；再往下一行會顯示目前綁定的專案，例如「講座籌備_demo」。

語音那顆麥克風 Gary 特別推。他說現在大多數人工作都在跟 AI 協作，一直打字手真的會很酸，所以他大概八成的時間都用語音輸入，也預告之後會出一支專門講語音輸入的影片。

### 視覺化註解：看到哪裡不順眼，點下去講一句就好

1. 在右欄預覽網頁的狀態下，把右上角的註解功能打開，工具列會出現「註解中」的標記。
2. 滑鼠移到畫面上任何一個元素，該區塊會被框起來，點下去就選中了。
3. 回到中間的對話框跟它說要怎麼改，Gary 舉的例子是「這個標題放大」「這張圖換掉」「這個區塊刪掉」。
4. 送出。Codex 會去改底層的程式碼，再把更新後的結果顯示給你。

送出之後，被選的區塊在預覽裡維持藍框並帶一個藍色圓點標記，Codex 進入思考狀態，開始改對應的原始碼。

介面到這裡就走完一輪。理解了 Codex 是個能動你檔案的 agent 之後，接下來才是影片裡他認為最關鍵的部分。
## 四個基本功（影片 4:39）

Gary 在 4:39 說，接下來是這支影片最關鍵的部分。前面已經知道 Codex 是個能動你檔案的 agent，那問題就變得很直接：一個能碰你電腦的東西，你得先學會駕馭它。

駕馭它靠四件事，專案、權限、上下文、AGENTS.md。

<img src="/images/blog/codex-beginner-guide/shot_0279s.jpg" alt="影片 4:39 章節交界的畫面，左側是 Codex 對話視窗，右側是它產出的 202606 講座預覽網頁，網頁上有文件整理、表格整理兩張說明卡">

這四個他沒有拆開講理論，直接拿一個例子從頭跑一遍：假設他最近要辦一場小型線下講座。影片後半畫面上一直在跑的那個「講座籌備_demo」資料夾，就是這個例子的實體。

### 基本功一：專案，先圈出一塊地給它（影片 4:57）

專案（Project）的概念在影片裡就一句話：你在哪個資料夾裡叫出 Codex，那個資料夾就變成它的工作區。它只會在這個範圍裡讀檔、改檔、新增或刪除。

<img src="/images/blog/codex-beginner-guide/shot_0309s.jpg" alt="橘色虛線框標示「工作區　Codex 只在這裡讀寫」，框內只有一行資料夾名稱「講座籌備/」">

所以 Gary 的第一步，是在電腦裡開一個資料夾叫「講座籌備」，把活動說明、報名名單、講者介紹、圖片素材、過去的簡報範本全部丟進去。

他特別提醒，這步看起來很基本，其實是整件事的關鍵。你做的動作是先圈出一塊範圍讓它在裡面做事，不用把整台電腦交給 AI，它也就不必在你整台電腦的茫茫檔案裡大海撈針。

影片裡那個 demo 資料夾長這樣：

<img src="/images/blog/codex-beginner-guide/shot_0325s.jpg" alt="Finder 視窗開在 講座籌備_demo 資料夾，列出兩份 pptx 簡報、三個版本資料夾 v0 v1 v2_待確認、老闆丟來的簡報需求.md、活動說明_草稿.md、處理日誌.md、報名名單_raw.csv、講者介紹.md、講座流程_old.md、圖片素材與雜亂素材_未整理等項目">

裡面有 `202606_講座_AI_Agent內訓_創造力版.pptx` 跟 `穩重版.pptx` 兩份簡報，`202606_講座資料_v0`、`v1`、`v2_待確認` 三個版本資料夾，`老闆丟來的簡報需求.md`、`活動說明_草稿.md`、`報名名單_raw.csv`、`講者介紹.md`、`講座流程_old.md`，還有「去年的一些其他素材」「雜亂素材_未整理」這種一看就知道會出事的資料夾。這種混亂程度，大部分人的電腦裡應該都有一份。

圈好範圍之後，第二件事是怎麼把檔案指給它。5:25 這段 Gary 講得很白：當你要 Codex 去處理某個檔案，與其只丟一個關鍵字叫它自己去找，不如直接指明。

<img src="/images/blog/codex-beginner-guide/shot_0328s.jpg" alt="Finder 裡三個資料夾 202606_講座資料_v0、v1、v2_待確認 被反白選取，下方出現拖曳中的三個檔名縮圖">

<img src="/images/blog/codex-beginner-guide/shot_0330s.jpg" alt="Codex 視窗畫面，橘色標籤標示「① 拖資料夾」與「直接把檔案指給它」，對話框底下已經掛上三個 202606_講座資料 的資料夾附件">

指明的方式有三種：

<img src="/images/blog/codex-beginner-guide/shot_0339s.jpg" alt="Codex 畫面上並排三個橘框標籤：① 拖資料夾、ⓘ 貼完整路徑、@ 用 @ 附檔，下方橫幅寫「指明檔案，省下亂找的時間與 token」">

- 拖資料夾：在 Finder 選好，直接拖進 Codex 的對話框
- 貼完整路徑
- 用 @ 附檔，也就是影片前段介紹過的小老鼠功能

不指明的代價，Gary 的說法是它會在你整台電腦東翻西找，一來慢，二來還白白燒掉一堆 token。

最後他把整件事收成一個名詞。讓 Codex 在特定專案資料夾裡工作，是為了讓它專注在重要的事情上，也是讓它不要改到非必要的檔案；而資料夾裡的文件整理這件事，說穿了就是 context engineering，上下文工程。聽起來很高大上，實際做的就是把檔案歸好類、名字取清楚，讓任何一個剛加入的人光看資料夾名稱就找得到東西。Gary 補了一句：就算沒有 AI 你本來也該這樣做，只是到了 agent 時代這件事只會更重要。

### 基本功二：權限，決定 Codex 能在你電腦上玩多大（影片 5:05）

Gary 說這是新手最該搞懂的一個。

權限設定就在對話框下方那個「請求核准」下拉選單裡，點開有三個選項。

<img src="/images/blog/codex-beginner-guide/shot_0366s.jpg" alt="Codex 視窗底部展開的核准模式下拉選單，三個選項為要求核准、代我核准、完整存取權，畫面上方橘色標題卡寫「權限三模式 決定 Codex 能玩多大」">

第一種是「要求核准」，也就是預設值，介面說明寫「一律先詢問是否要編輯外部檔案及使用網際網路」。Gary 的白話版是：它只能讀檔案、跟你討論，要真的動任何檔案、跑任何指令，都得先問過你。

<img src="/images/blog/codex-beginner-guide/shot_0381s.jpg" alt="核准模式下拉選單旁的橘色說明卡「① 要求核准：只能讀檔、討論／動任何檔案、指令都先問你」">

第二種是「代我核准」，介面說明是「僅對偵測為可能不安全的操作要求核准」，也是大部分人在用的。它在你交給它的那個工作資料夾裡面可以自己讀檔、改檔、跑指令，不用一直問你；但只要它想碰資料夾以外的東西，或者要連網，就會停下來問你一聲。

<img src="/images/blog/codex-beginner-guide/shot_0391s.jpg" alt="下拉選單中「代我核准」被游標選中，旁邊綠色說明卡「② 待我核准：工作區內自由讀改跑／越界、連網才問你」">

順帶一提，Codex 介面上寫的是「代我核准」，Gary 影片字卡上寫的是「待我核准」，指的是同一個模式。

第三種是「完整存取權」，介面說明「可無限制存取網際網路和您電腦上的任何檔案」，也就是 Full Access。連網路、連整台電腦都能碰，不再問你。Gary 說它在 CLI 裡還有個外號叫 YOLO 模式，You only live once，反正你只活一次，豁出去就對了。

<img src="/images/blog/codex-beginner-guide/shot_0399s.jpg" alt="下拉選單中「完整存取權」被游標指著，旁邊紅框說明卡「③ Full Access：連網路、整台電腦／CLI 叫 YOLO」，底部紅色警告條寫「新手別亂開」">

這個模式他**不建議新手亂開**。agent 的權限是一把雙面刃，權限越高你越省事，可是萬一你還搞不清楚它在幹嘛，它一個動作就能捅出大簍子。

<img src="/images/blog/codex-beginner-guide/shot_0412s.jpg" alt="同一張 Full Access 說明卡，畫面下緣多出一條紅色橫幅「雙面刃 越高越省事 → 越易出事」">

那到底要選哪個？Gary 說不用一開始就糾結，比較聰明的做法是先用保守一點的起手，然後讓它問你。

<img src="/images/blog/codex-beginner-guide/shot_0421s.jpg" alt="深色投影片，橘色編號 01 加箭頭，文字寫「保守起手 讓它問你」">

被那個要不要同意的視窗問到煩了也沒關係，那個視窗當下就能直接切到更高的權限，或者按「這個工作階段不要再問我」。一開始被問個幾次是正常的，等你摸清楚這些運作邏輯之後再慢慢放手。

等比較熟了還有一種組合：平常直接開 Full Access 圖個順暢，但用 AGENTS.md 把那些不可逆的操作鎖死，比如在裡面直接寫一條「不要刪除原始檔」。這樣一邊享受最高權限不用一直被問問題，一邊又把最怕的那種手滑刪掉東西擋在門外。

<img src="/images/blog/codex-beginner-guide/shot_0450s.jpg" alt="投影片左邊 Full Access 卡片標「平常起手：無痛放行、不用一直被問」，右邊 AGENTS.md 卡片標「把不可逆操作鎖死」並紅框標示「不要刪除原始檔」，中間橘色圓標「又快又擋手滑」，底下灰框寫「仍是自然語言設限，不是 100% 保險」">

這招別當成保險。Gary 自己在畫面上就掛了警語：某種程度上你還是在用自然語言的方式去限制 agent 的行為，使用上還是要小心。

### 基本功三：上下文，別讓它塞爆（影片 6:36）

上下文可以理解成 AI 視野範圍內能讀到的資料，包括你跟它說過的話、你給它的文件之類的。

<img src="/images/blog/codex-beginner-guide/shot_0459s.jpg" alt="示意圖，紫色大圓標「AI 視野」，圓心一顆橘色小球標「焦點」">

Gary 說你給它越多上下文、越多要求、越多歷史對話，它能參考的東西就越多，但這不代表越多越好。要讀的東西一多，它能思考的空間就被壓縮，焦點也容易模糊。

<img src="/images/blog/codex-beginner-guide/shot_0471s.jpg" alt="同一張 AI 視野示意圖，圓周上塞滿需求、文件、對話、規則、更多文件、歷史對話六個標籤，中央焦點縮成一小點，下方文字「越多上下文 ≠ 越好」">

他拿助理打比方：你一次丟給助理十份文件、二十條規則、三個任務，中間還一直改方向，他不是不能做，但很容易抓錯重點。

實際做法是一個階段做完就收一次。回到那場講座，當名單整理完、活動頁也做好了，Gary 會讓 Codex 先總結一下目前的狀態，然後把總結複製貼上，開一個新的 session。

<img src="/images/blog/codex-beginner-guide/shot_0489s.jpg" alt="Codex 對話畫面，右側送出一則使用者訊息「總結目前狀態」，下方顯示「正在思考」，上方是先前產出的 173 個檔案與 4.6 MB 壓縮檔清單">

另一個做法是直接輸入斜線指令 compact，也就是壓縮上下文，把它的腦袋清乾淨，讓它專心做下一件事。

<img src="/images/blog/codex-beginner-guide/shot_0494s.jpg" alt="Codex 對話畫面顯示「正在壓縮上下文」的進行中狀態，上方掛著 202606_講座_A方案_整理清單.md 與 處理日誌.md 兩個檔案卡">

Codex 介面上會顯示目前上下文用了多少，通常是一個小圈圈或一個百分比。影片裡壓縮完之後跳出的狀態卡是這樣：

<img src="/images/blog/codex-beginner-guide/shot_0502s.jpg" alt="Codex 介面出現「上下文已精簡」分隔線與狀態卡，列出工作階段 ID、上下文剩餘 94%（已使用 14,305，總計 258K）、速率限制無法使用">

Gary 的習慣是大概到 80% 就手動壓一次，不要等它滿了自己壓。理由是萬一你任務做到一半剛好撞到 100%，它被迫自動壓縮，很容易把重要的東西漏掉，得不償失。

### 基本功四：AGENTS.md，這個專案的規則書（影片 8:35）

<img src="/images/blog/codex-beginner-guide/shot_0519s.jpg" alt="深色投影片上一張橘框卡片，紅色書本圖示配等寬字 AGENTS.md，底下標「專案規則書」">

AGENTS.md 可以先想成專案的規則書。用過 Claude Code 的人，它就等於 Claude Code 的 CLAUDE.md。

Gary 說第一次看到可能會想「怎麼又要寫一個 markdown 文件」，但它真的很實用。影片裡他在講座籌備資料夾放的那份，畫面下方顯示字數 64：

<img src="/images/blog/codex-beginner-guide/shot_0539s.jpg" alt="文字編輯器視窗標題為 講座籌備/AGENTS.md，內容為「# 講座籌備 規則」加四條條列，狀態列顯示字數 64、格式 Markdown">

```markdown
# 講座籌備 規則
- 請用繁體中文輸出
- 不要刪除原始檔
- 修改文件前先說明你要改哪裡
- 報名名單一律輸出成一份 Excel
```

截圖裡最後還有一條空的減號正在打，旁白唸的是第五條「做完附上處理摘要」。

寫完之後，你每次在這個專案下開 session，Codex 都會先讀這份文件，把它當成最高指導原則。

<img src="/images/blog/codex-beginner-guide/shot_0558s.jpg" alt="投影片上的 AGENTS.md 卡片，列出四條規則：請用繁體中文輸出、不要刪除原始檔、報名名單輸出成 Excel、改檔前先說明改哪裡">

Gary 給 AGENTS.md 的定位很簡單：重要的事情講一次就好。把你的偏好跟雷點寫進去，它就更懂你，產出的東西也更對味。

接下來是新手很容易踩的坑，以為這份文件寫越多越好，把所有流程、所有 SOP 通通塞進去。影片裡那張卡片就從四條長到六條，多出「命名格式 YYYYMMDD_主題」跟「每段流程都要寫 commit」。

<img src="/images/blog/codex-beginner-guide/shot_0560s.jpg" alt="同一張 AGENTS.md 卡片變成六條規則，新增命名格式 YYYYMMDD_主題與每段流程都要寫 commit 兩條">

這樣反而會扣分。因為它每開一個 session 都要先把整份讀一遍，規則越肥，它真正拿來思考你任務的空間就被吃掉越多，回答品質反而會掉。

<img src="/images/blog/codex-beginner-guide/shot_0575s.jpg" alt="六條規則的 AGENTS.md 卡片下方出現紅字流程「規則越肥 → 思考空間被吃 → 品質掉」，再下面一列綠框寫「只放最低限度背景・長流程做成 Skill」">

比較好的做法是 AGENTS.md 只放每次都一定要知道的最低限度背景跟規矩，那些比較長的操作流程做成 Skill，要用再叫出來就好。

還有一個省事的起手式。Gary 說你不用一開始就對著一個空白檔案發呆，可以先正常用它做一陣子，等專案有了點樣子，再叫 Codex 根據你們這段時間的合作幫你把 AGENTS.md 生出來。它會把專案背景、檔案結構、你的偏好都整理進去，比從零硬寫好用多了。

<img src="/images/blog/codex-beginner-guide/shot_0593s.jpg" alt="三段式流程投影片：01 先正常用它做一陣子、02 叫 Codex 根據合作生成 AGENTS.md、03 自動整理背景／檔案結構／偏好">

### AGENTS.md 跟 Memory 差在哪（影片 9:55）

這是影片裡被單獨拉出來回答的一個疑惑。

<img src="/images/blog/codex-beginner-guide/shot_0614s.jpg" alt="左右對照投影片，中間一個 VS 圓標，左邊 AGENTS.md 條列你親手寫的員工守則、專案的規定（命名／格式／禁區）、跟著資料夾走，右邊 Memory 條列 AI 私下的觀察筆記、越來越懂你、但可能過度解讀">

AGENTS.md 是你親手寫的員工守則，是這個專案的規定。怎麼命名、輸出成什麼格式、哪些不能碰，都寫在這裡，它跟著資料夾走。

Memory 比較像 AI 私底下對你的觀察筆記。它在跟你合作的過程中，覺得這個人好像有這個偏好，就自己記下來。好處是它會越來越懂你，壞處是它可能會過度解讀。Gary 舉的例子很具體：你可能只是上禮拜試了一個框架，後來沒用了，它卻以為那是你的長期習慣。

所以 Memory 記了不能放著不管，要定期清。最簡單的方法就是直接問 Codex「你現在記了我哪些東西」，然後告訴它哪些可以刪掉。

<img src="/images/blog/codex-beginner-guide/shot_0639s.jpg" alt="總結投影片標題「快速總結：兩邊各司其職」，左邊紫框大腦圖示標 Memory 對應個人長期偏好，右邊橘框書本圖示標 AGENTS.md 對應專案規則加地雷">

分工是這樣：個人長期偏好交給 Memory，專案規則跟地雷寫進 AGENTS.md。

### 實例演練：講座籌備資料夾裡，Codex 到底做了什麼

這整章的畫面底下其實一直在跑同一個 demo。8:07 前後，也就是 Gary 講到「讓 Codex 先總結一下目前的狀態」那句時，畫面停在 Codex 處理這個講座籌備資料夾的成果上。這段值得逐條看，因為它就是前面四個基本功全部生效之後的樣子。

<img src="/images/blog/codex-beginner-guide/shot_0487s.jpg" alt="Codex 對話畫面列出處理成果：整理清單 md、完整整理版 20260611 資料夾內含 173 個檔案、備份壓縮檔 zip 約 4.6 MB，下方另有待確認事項與處理摘要兩段">

Codex 交出來的東西：

- 整理清單 `202606_講座_A方案_整理清單.md`
- 完整整理版 `202606_講座_完整整理版_20260611`，裡面有 173 個檔案，包含主分類、完整掃描清單、處理日誌、會議預覽網頁、簡報輸出，以及原始來源保留資料
- 備份壓縮檔 `202606_講座_完整整理版_20260611.zip`，約 4.6 MB

那個 4.6 MB 中間還出過一次意外。回頭看 6:06 的畫面，Codex 第一次壓出來的 zip 是 4.8 MB，它自己檢查 zip 內容時發現 macOS 附加的 `._` 資源檔也被打包進去了，於是改用不含這類附加檔的方式重新壓一次，才變成後來乾淨的 4.6 MB，最後又列了一次檔案確認 zip 裡真的沒有 `._`。這段沒有人叫它做，它自己抓出來自己補。

比成果更值得看的，是它沒有做的事，還有它留下來的東西。畫面上那份輸出的後半段有兩個區塊：

- 待確認事項：報名名單目前仍是 raw 檔，尚未產出 `202606_講座_報名名單_整理版.csv`；`final 真的最後版.md` 跟 `不要用_舊版標題.txt` 仍保留在 `00_待確認` 區
- 處理摘要的最後一句：原始資料未刪除、未覆蓋

這兩點正好對上 AGENTS.md 裡的「不要刪除原始檔」跟「做完附上處理摘要」。規則書怎麼寫，產出就照著長。

<img src="/images/blog/codex-beginner-guide/shot_0491s.jpg" alt="Codex 回覆的總結，條列已產出的整理清單、完整整理版、備份壓縮檔、會議預覽網頁 index.html、已更新的處理日誌.md，並註明 173 個檔案、zip 約 4.6 MB、原始資料沒有刪除">

Gary 在這裡送出的指令只有五個字：總結目前狀態。Codex 把已產出的清單、173 個檔案、4.6 MB 的 zip、還沒動的待確認項目重講一次，這份總結就是他要複製去開新 session 的內容。

還有一個容易忽略的細節：那個資料夾裡本來就放了一份「處理日誌.md」，Codex 每做完一段就同步更新它一次。等於你不在的時候，它自己留了一份工作紀錄給你查。

### 從基本功接到實際任務

四個基本功走完，影片在 10:44 轉進實際應用。Gary 把場景說得很清楚：你手上有一份報名名單、一份活動說明、幾張圖片、一份講者介紹，還有老闆丟給你的簡報需求。

<img src="/images/blog/codex-beginner-guide/shot_0665s.jpg" alt="章節轉場投影片，標題「辦一場講座・一堆瑣事要做」，畫面中央一疊卡片，最上面一張寫「整理講者介紹」">

以前這種任務最煩的地方，是要先打開資料夾看哪個檔案是最新版，然後整理名單、檢查信箱、整理部門、做簡報，可能還要做活動頁。每一件事都不難，就是很碎。Gary 說 Codex 最適合的就是替你處理這種繁瑣的任務。
## 實戰：檔案、表格、簡報（影片 11:08）

四個基本功講完，Gary 把場景切到一件很多人週一早上都在做的事：辦一場講座。

手上的東西大概是這些，一份報名名單、一份活動說明、幾張圖片、一份講者介紹，還有老闆丟過來的簡報需求。以前處理這種任務的順序是打開資料夾、看哪個檔案是最新版、整理名單、檢查信箱、整理部門、做簡報，可能還得生一個活動頁。Gary 的形容很精準：「每一件事都不難，但就是很碎。」

<img src="/images/blog/codex-beginner-guide/shot_0668s.jpg" alt="影片轉場畫面，上方標題寫著「辦一場講座 · 一堆瑣事要做」，中央一張傾斜的橘框標籤卡片寫著「Codex 專治這種繁瑣」">

下面三步是影片裡實際示範的流程。照著走一遍，一包散檔案可以收成能交出去的成品。

### 第一步：讓它掃資料夾，順便把檔名改成人看得懂的

開場先別急著叫它做東西。讓 Codex 掃一遍資料夾，把裡面有哪些文件、每個大概是做什麼用的列出來，然後幫你重新命名。

<img src="/images/blog/codex-beginner-guide/shot_0671s.jpg" alt="影片示意畫面，一張標題為「檔名看不懂」的卡片，裡面列出四個檔案：最終版.docx、真的最後版.docx、這次絕對最終版.docx、final_v2_真的.docx">

畫面上這四個檔名，大概每台電腦裡都躺著雙胞胎：最終版.docx、真的最後版.docx、這次絕對最終版.docx、final_v2_真的.docx。Gary 說檔名看不懂，很多時候就是工作開始亂掉的第一步。你得一個一個打開來看最後修改日期，來回比對，很耗時間。

命名的方向他給了具體示範：把「final 真的最後版」改成「202606 講座活動說明」。日期在前，內容在後。

可以直接講給 Codex 聽的版本（影片沒有逐字打出提示詞，這是照 Gary 描述的作法整理的講法）：

> 掃描這個資料夾，列出每個檔案是什麼、內容大概在講什麼，然後依照「年月＋用途」的規則重新命名，例如 202606 講座活動說明。動手改之前，先把新舊檔名對照表給我看。

最後那句對照表值得留著。重新命名會動到你原本靠肉眼認得的檔案，先看過對照表再放行，比事後回頭猜哪個是哪個省事得多。

整理乾淨的好處不只在這一步。Gary 提醒，後面不管是你自己接手還是讓 AI 接手，都會輕鬆很多。

### 第二步：整理表格，講目的比講動作有用

這一段藏了一個小訣竅，我認為是整支影片最值得抄走的一句：你跟它講目的，結果會差很多。

<img src="/images/blog/codex-beginner-guide/shot_0710s.jpg" alt="影片對比畫面，標題「講目的 · 結果差很多」，左邊灰色卡片標示「只說做什麼」寫著「幫我整理名單」，右邊橘色高亮卡片標示「講出目的」寫著「幫我整理一份等下要寄確認信的名單」">

左邊那句「幫我整理名單」，Codex 只能猜你想要什麼。右邊那句「幫我整理一份等一下要拿來寄確認信的名單」多給了一個用途，它就懂得把信箱、是否出席這些欄位擺前面，把不相關的欄位收起來。同一份資料，排出來的表完全兩樣。

以講座報名名單來說，影片點名要留的欄位是姓名、部門、信箱、是否出席、飲食需求，整理成一張只留重要資訊的 Excel。

> 這份報名名單我等一下要拿來寄出席確認信。幫我整理成一張 Excel，只留姓名、部門、信箱、是否出席、飲食需求，寄信會用到的欄位放前面。

### 一定要跟它要一份處理日誌

表格整理完不要就收工。Gary 說這一步很重要：請它順便產出一份處理日誌，寫清楚它改了什麼、有哪些資料缺漏、哪些人需要補信箱。

<img src="/images/blog/codex-beginner-guide/shot_0728s.jpg" alt="影片示意的處理日誌畫面，第一列「重新命名 6 個檔案、合併 2 份名單」右側標記「改了什麼」，第二列「3 筆 Email 欄位空白」右側標記「資料缺漏」，下方另起一行寫著「王小明、李華 需補信箱」">

畫面上那份示意日誌長這樣：重新命名 6 個檔案、合併 2 份名單，這是「改了什麼」；3 筆 Email 欄位空白，這是「資料缺漏」；再往下具體點名王小明、李華需要補信箱。

理由 Gary 講得很直白：Codex 不是魔法，你得知道它做了什麼，才有辦法驗收。合併名單、去重複、補欄位這些動作，做完之後光看結果看不出它當初怎麼判斷，沒有日誌你只能整份重看一次。

日誌還順手幫你把待辦挑出來了。三個信箱空白，代表這三個人的確認信寄不出去，這件事在按下寄送之前就要知道。

### 串下去：一人一封確認信

有了那張乾淨的 Excel，Gary 說可以往下串接 Gmail，叫 Codex 針對每個人寫一封確認信。

再進一步的玩法是讓它去讀報名者填的備註欄。有人在備註裡提了特殊需求，就在那個人的信裡客製化回應他的疑問，其他人維持一般版本。人工做要一封一封看，交給 Codex 就是多交代一句話的事。

這一段影片只有口述，沒有操作畫面。串 Gmail 這類第三方服務的做法，影片後面談外掛程式時會再提到。

### 第三步：簡報先列架構，別直接生投影片

<img src="/images/blog/codex-beginner-guide/shot_0755s.jpg" alt="影片畫面「簡報草稿 · 先列架構」，下方四張編號 1 到 4 的深色卡片，每張卡片內以灰色線條示意條列內容">

做簡報的順序同樣是先架構後內容。Gary 的做法是讓 Codex 根據活動說明和講者介紹先列出簡報架構，他當場報出來的順序是：第一頁活動背景，第二頁流程，第三頁講者介紹，後面接報名資訊跟注意事項。

架構列出來，你才有東西可以改。頁數不對、順序怪、少一頁 QA，這時候調整只是改一行字。等它把二十頁投影片都生完再說要換順序，成本完全不同。

### 活動頁：用 Planning Mode，還可以叫它當 PM 反問你

講座如果還要一個活動頁，Gary 建議用 Planning Mode，這個功能適合比較複雜的任務。

他特別提醒別一上來就丟「幫我做一個網站」，這樣很容易做歪。比較好的做法是先叫它列計畫。

<img src="/images/blog/codex-beginner-guide/shot_0781s.jpg" alt="影片示意畫面，上方紫框標籤「Planning Mode 複雜任務專用」，對話框中使用者訊息「幫我做一個活動報名頁」，Codex（PM 模式）回覆「先別急。風格要正式還是輕鬆？需要報名按鈕嗎？目標對象是誰？」，下方橘框提示「複雜任務 → 先列計畫，別叫它直接做網站」">

更進階一點的用法，是請 Codex 扮演一個 PM，針對你沒講清楚的地方反過來問你，問到網頁規格被定義清楚為止。畫面上的示範是使用者說「幫我做一個活動報名頁」，Codex 回一句「先別急」，接著問風格要正式還是輕鬆、需不需要報名按鈕、目標對象是誰。

> 我要做一個講座活動報名頁。先別動手，你扮演 PM，把規格不清楚的地方一條一條問我，問到你有把握為止，再把計畫列給我看。

等你的需求被釐清，它提的計畫看起來也合理，再讓它動手。這個先問後做的順序，是複雜任務不做歪的關鍵。

### 圖片交給 image 2

<img src="/images/blog/codex-beginner-guide/shot_0788s.jpg" alt="影片畫面上方紫框標籤「image 2 生成」，下方兩張並排卡片分別寫著「活動主視覺」與「簡報封面」，背景是一個人坐在電腦前的暗色剪影">

需要圖片的話，Gary 說 Codex 也可以用目前最新的圖像生成模型 image 2，幫你做活動主視覺、簡報封面或者講者卡片。畫面上舉的兩個例子就是活動主視覺和簡報封面。

### 做出來不對？在預覽上直接點

網頁做出來不對也沒關係。Gary 把前面講過的視覺化註解接回來用：你不用每次都很抽象地描述哪裡要改，在預覽裡直接點那個地方，然後像在跟同事交代需求一樣，打開語音或者打字跟它說。

他示範的口吻是這樣：最上面那一條橫條放大，標題的贅字刪掉，按鈕往上挪一點。

點哪裡改哪裡，用日常說話的方式交代修改。Gary 對這個階段的評語是：做到這裡，其實你已經在 Vibe Coding 了。

基本使用場景到這裡告一段落。影片接著往上加碼，講怎麼用 Skill 跟外掛程式把 Codex 的能力再推一層。
## Skill、外掛程式與自動化（影片 13:38）

基本操作講完之後，Gary 把最後一段留給三件事：Skill、外掛程式、自動化。他的定位很明確，這三個是拿來「讓 Codex 再升一級」的，前面學的是怎麼指揮它做單一任務，這裡學的是怎麼讓它把同一件事重複做好、做久。

<img src="/images/blog/codex-beginner-guide/shot_0818s.jpg" alt="影片章節標題卡，深色背景中央寫著「讓 Codex 再升一級」，左上角標示「實際應用」">

### Skill：把跑通過的流程存起來，下次不用重講

Gary 給 Skill 的定義是「一套你自己定好的 SOP」。平常你跟 Codex 講一個複雜任務，得從頭交代背景、步驟、輸出格式，講完它才動；下次同樣的事再來一次，你又得重講一遍。Skill 就是把那套已經跑通、你自己也滿意的方法存下來，之後直接叫它就好。

<img src="/images/blog/codex-beginner-guide/shot_0825s.jpg" alt="簡報畫面，橘色直線標題「Skill = 跑通一次就存起來的 SOP」，下方字幕講到把已經跑通、自己也滿意的方法存起來">

他舉的例子是一個叫「講座籌備」的 Skill。這個 Skill 裡面包含的不是一個動作，是一整串：讀取報名資料、整理名單跟缺漏欄位、產生邀請信草稿。

<img src="/images/blog/codex-beginner-guide/shot_0836s.jpg" alt="簡報上三個橘色圓形圖示依序排開：讀取報名資料、整理名單／缺漏欄位、產生邀請信草稿">

活動辦完之後還有第四步，產出活動狀態與復盤摘要。四個步驟串成一條線，下次再辦類似的活動，Gary 說就不用重講一遍，這就是 Skill 的價值。

<img src="/images/blog/codex-beginner-guide/shot_0845s.jpg" alt="簡報上四個步驟圖示完整呈現：讀取報名資料、整理名單／缺漏欄位、產生邀請信草稿、活動狀態／復盤摘要，下方有一顆按鈕寫著「完整教學連結放資訊欄」">

要注意的是，這支影片沒有實際示範 Skill 怎麼建立、檔案長什麼樣、要放哪裡。Gary 在這裡直接說他另外有一支影片專門講 Skill 的製作實戰教學，完整連結放在影片資訊欄，有興趣的人自己去看。所以如果你看到這段想照做，這一節能給你的是「Skill 是什麼、什麼樣的流程適合做成 Skill」，實際製作步驟得追那支影片。

判斷哪些流程值得做成 Skill，可以照講座籌備這個例子的特徵抓：步驟固定、會重複發生、每次的差別只在資料本身。報名名單每次不一樣，但「怎麼整理報名名單」每次都一樣，這種就適合。

### 外掛程式：讓 Codex 直接進到你原本在用的工具裡

第二個是外掛程式。Gary 的說法是，外掛程式讓 Codex 串接並直接使用第三方的應用程式。差別在於，沒接外掛之前，Codex 能動的只有你電腦上的檔案；接上之後，它能直接進到 Gmail、Drive 這些服務裡面做事。

<img src="/images/blog/codex-beginner-guide/shot_0848s.jpg" alt="Codex 桌面版畫面，左側欄由上而下是新聊天、搜尋、外掛程式、自動化（右邊標著數字 2），下方專案區有「講座籌備_demo」；右側對話顯示整理清單、完整整理版、備份壓縮檔、會議預覽網頁、處理日誌.md 等產出，並註明完整整理版目錄有 173 個檔案、備份 zip 約 4.6 MB">

安裝的路徑很短。點左側欄位的「外掛程式」，會進到一個獨立頁面，標語寫「在你喜愛的各種工具中與 Codex 協作」，上方分成「外掛」和「技能」兩個分頁，中間是一條搜尋框，寫著搜尋外掛與技能，旁邊還有一個「OpenAI 精選」的篩選標籤。

<img src="/images/blog/codex-beginner-guide/shot_0856s.jpg" alt="Codex 外掛程式頁面剛開啟的狀態，上方有「外掛」「技能」兩個分頁、搜尋框、OpenAI 精選篩選標籤，內容區還在載入">

頁面載入完會看到兩區。上面是「已連線」，一排已經接好的服務圖示；下面是 Featured 推薦清單，影片畫面上看得到 GitHub（Triage PRs, issues, CI, and publish flows）、Slack（Read and manage Slack）、Data Analytics（Turn data into clear decisions）、Product Design（Explore and prototype ideas）、Creative Production，每一個右側都有一顆「連接」按鈕。

<img src="/images/blog/codex-beginner-guide/shot_0859s.jpg" alt="外掛程式頁面載入完成，上方「已連線」區有一排服務圖示，下方 Featured 清單列出 GitHub、Slack、Data Analytics、Product Design、Creative Production，每項右側都有「連接」按鈕">

如果你要的服務不在推薦清單裡，就用搜尋。Gary 示範的是 Gmail：搜尋框打 gmail，結果區出現「外掛 1」，底下就是 Gmail，說明寫 Read and manage Gmail，右邊一顆「連接」。

<img src="/images/blog/codex-beginner-guide/shot_0863s.jpg" alt="外掛程式搜尋框輸入 gmail，結果顯示「外掛 1」，下方是 Gmail 項目，說明為 Read and manage Gmail，右側有連接按鈕，畫面中央浮現安裝中的卡片">

按下去之後畫面中央會跳出一張卡片，上面是 ChatGPT 圖示和 Gmail 圖示並排，文字寫「正在新增 Gmail…」，底下標註由 OpenAI 開發。整個過程就是一鍵，不用去申請 API key，也不用寫設定檔。

<img src="/images/blog/codex-beginner-guide/shot_0868s.jpg" alt="安裝中的卡片放大顯示，ChatGPT 圖示與 Gmail 圖示並排，文字為「正在新增 Gmail…」，下方標註由 OpenAI 開發">

接完能做什麼？Gary 舉了兩個。接 Gmail，它就能進到你信箱搜尋信件、撰寫草稿。接 Drive，它就能讀你的雲端文件，甚至按你的要求改特定的檔案。這裡值得停一下：讀信、改雲端檔案都是會動到真實資料的權限，接之前想清楚你要給它多大範圍，這跟前面章節講的核准機制是同一件事的延伸。

### 自動化：用一句話設定每天早上九點的排程

第三個是自動化，也是這一段唯一從頭到尾完整示範的功能。Gary 的定義是把你每天固定要跑的任務交給 Codex，讓它按時幫你做。

設定方式比想像中直覺，不用去翻設定頁，直接在對話框用中文講。影片裡 Gary 輸入的原句是：「幫我設定一個自動化任務，每天早上9點 自動檢查報名表單，如果有新報名的，就更新到文件夾裡的excel」。就這樣一句，沒有格式、沒有 cron 語法。

Codex 回的是一段確認：已設定好自動化任務「202606 講座報名表單每日同步」，狀態 ACTIVE，會每天早上 9:00 在這個講座專案裡執行同步腳本。同時它把正式名單也產出來了，202606_講座_報名名單_整理版.xlsx 和同名的 .csv。

<img src="/images/blog/codex-beginner-guide/shot_0878s.jpg" alt="Codex 對話畫面，使用者訊息為「幫我設定一個自動化任務，每天早上9點 自動檢查報名表單，如果有新報名的，就更新到文件夾裡的excel」，Codex 回覆已設定好自動化任務 202606 講座報名表單每日同步、狀態 ACTIVE、每天早上 9:00 執行，並列出產出的 xlsx 與 csv 名單檔">

再往下是處理摘要，這段比「設定成功」四個字有用得多。Codex 說明它先用現有的 報名名單_raw.csv 當表單回覆來源，手動跑了第一次新增 10 筆，第二次確認新增 0 筆、未變更 10 筆，不會重複寫入，Excel 檔也已驗證可讀。等於它自己先做了一次冪等性驗證才把排程交出去。

<img src="/images/blog/codex-beginner-guide/shot_0883s.jpg" alt="Codex 回覆的處理摘要段落，說明先用現有 報名名單_raw.csv 作為表單回覆來源，手動跑第一次新增 10 筆、第二次確認新增 0 筆未變更 10 筆、不會重複寫入，Excel 檔已驗證可讀">

最後一段是排程的落地細節。Codex 把設定寫進 registration-sync.config.json，日誌寫進「報名表單同步日誌.md」，並且主動註明一個限制：目前沒有找到真正的 Google 表單回應 Sheet／CSV 連結，所以排程現在讀的是資料夾裡的 raw CSV，把真正表單的 CSV／Sheet 匯出檔給它，就會接到正式表單來源。畫面下方看得到排程已經建立，條目寫著「於每天的 上午9:00」，左側欄「自動化」旁邊的數字也對應著已有的排程數。

<img src="/images/blog/codex-beginner-guide/shot_0887s.jpg" alt="Codex 回覆下半段，列出 registration-sync.config.json 與報名表單同步日誌.md，並註明目前沒找到真正的 Google 表單回應 Sheet／CSV 連結、排程暫時讀資料夾裡的 raw CSV；下方排程條目顯示「於每天的 上午9:00」，另有 README.md、處理日誌.md、202606_講座_報名名單_整理版.xlsx 三個檔案">

這個限制值得抄下來當自己設排程的檢查點：**排程能不能真的跑起來，取決於資料來源穩不穩定**。Codex 在示範裡沒有硬幹，它接了手邊有的 CSV，然後把缺的那一塊明講出來。你自己設排程時如果沒看到這種說明，反而該回頭問它到底讀的是哪一份資料。

Gary 口頭上還提了另一個自動化情境，影片沒實際做：每天去撈那些還沒回信的人，幫你寫一封客製化的 follow up。配合前面接好的 Gmail 外掛，這是同一套機制的延伸用法。

### 為什麼連五分鐘的小事都值得排程

這段最後 Gary 花了十幾秒講一個觀念，而且講得比功能本身重。

他說很多人會有強迫症，覺得任務這麼小，沒必要交給 AI。但很多人的時間，就是每天被這些瑣事一點一點磨掉的。一件瑣事可能只花你五分鐘，可是你要記得去做這件事的心智成本，絕對不只五分鐘。

收尾那句他講得很直白：自動化排程不是拿來炫技的，是讓 AI 去扛那些固定要做、又很制式的事情，把你的腦子空出來。

三個功能放在一起看，其實是三種不同的省法。Skill 省的是重複交代流程的力氣，外掛省的是在工具之間搬資料的力氣，自動化省的是「記得要做」這件事本身的力氣。
## 把 Codex 當家教（影片 15:01）

### 一件瑣事只花五分鐘，代價卻不只五分鐘

講完自動化排程，Gary 先擋掉一個很多人都有的心理障礙：覺得任務這麼小，沒必要交給 AI。

他的說法是，不用有這種強迫症。很多人的時間，就是每天被這些瑣事一點一點磨掉的。一件瑣事可能只花你五分鐘，但你要記得去做這件事的心智成本，絕對不只五分鐘。

投影片把這筆帳拆得很清楚。以「回覆報名信」為例，檯面上的成本是 5 分鐘，檯面下還有三筆：記得要做、怕漏掉、分心切換。三筆加起來，真正成本遠遠大於 5 分鐘。

<img src="/images/blog/codex-beginner-guide/shot_0901s.jpg" alt="投影片標題「一件瑣事 = 5 分鐘？」，「回覆報名信」對應 5 分鐘，下方另列「＋記得要做」「＋怕漏掉」「＋分心切換」，結論是「真正成本 ≫ 5 分鐘」與「交給自動化 → 解放你的腦子」">

所以 Gary 說，自動化排程不是拿來炫技的，它是在解放你的腦子，讓 AI 去扛那些固定要做、又很制式的事情。你省下的不只是那五分鐘，還有「一直記著這件事」佔掉的那塊注意力。

### 它是助理，也是隨叫隨到的家教

影片最後，Gary 想講一個很多人會忽略的觀念。前面整支影片都在談怎麼指揮 Codex 做事，但他認為它的價值不只這樣。

<img src="/images/blog/codex-beginner-guide/shot_0905s.jpg" alt="深色投影片中央一張橘框卡片，上排小字「幫你執行任務」，下方橘色大字「私人助理」">

很多非技術背景的人會覺得，這種工具是工程師在用的，我又不懂，不敢碰。Gary 的回應是千萬不要妄自菲薄：Codex 除了是你的私人助理，它其實也是你隨叫隨到的家教。

他說這也是影片開頭那位運營夥伴一路用下來最大的心得。那位夥伴完全不寫程式，剛開始用 Codex 時問 Gary 的第一個問題是「這不就是一個放在桌面上的 ChatGPT 嗎？」（影片 00:13）。用到後來，讓他最有感的就是這件事：不會的東西，可以直接問它。

### 例子一：看不懂別人寫的 Skill，就直接丟給它問

第一個例子很貼近新手的處境。你拿到一個別人寫好、感覺很強但有點複雜的 Skill，打開來不知道怎麼用。

以前的做法是自己硬讀。Gary 的做法是直接把它丟給 Codex，然後問三件事：

1. 這個 Skill 是做什麼的？
2. 什麼情況會觸發？
3. 該怎麼改才適合我的工作？

影片裡實際打進 Codex 對話框的就是這一整句。前兩問是搞懂它，第三問才是關鍵：Gary 特別強調要「再進一步告訴它你平常的工作內容」，Codex 知道你在做什麼，改出來的版本才會貼著你的流程走。

<img src="/images/blog/codex-beginner-guide/shot_0933s.jpg" alt="Codex 對話視窗裡送出的訊息「這個 Skill 是做什麼的？什麼情況會觸發？該怎麼改才適合我的工作？」，畫面下方字幕「再進一步告訴它你平常的工作內容」">

### 例子二：裝新工具，讓它邊裝邊教你

第二個例子是安裝新工具。Gary 說以前我們太習慣什麼都自己來：去啃 GitHub 的 README、看一堆手把手教學，中間有一個畫面長得跟教學不一樣，你就卡住了。

<img src="/images/blog/codex-beginner-guide/shot_0961s.jpg" alt="投影片「例子 2：裝新工具」左右對照，左欄「以前 什麼都自己來」列出啃 GitHub README、看一堆手把手教學、畫面不一樣就卡住；右欄「現在 交給 Codex」列出「幫我裝好」「一步步教我怎麼用」「給我一張注意事項＋技巧表」，底下寫「不用會寫 code，邊 vibe 邊學」">

現在你可以把這句話原封不動丟給 Codex：

> 你先幫我裝好，然後一步一步教我怎麼用，順便給我一張表，整理出我要注意的地方跟一些小技巧。

這句指令其實塞了三個要求：裝好、教會、留下一張可以回頭查的筆記。第三個要求特別值得學起來，因為那張表就是你下次不用再問一次的東西。

不會寫程式沒關係，你可以讓它邊做邊解釋。Gary 說這一樣是前面講過的 vibe coding，只是這一次，你 vibe 的同時，其實也在學。

### 把它當一個新來的同事帶

不過家教也好、助理也好，Gary 提醒你的角色是 agent 的管理者。不能把任務丟給它，就預設它會生出你腦子裡那個完美的版本。

<img src="/images/blog/codex-beginner-guide/shot_0963s.jpg" alt="投影片只有一行標題「把它當新來的同事帶」，畫面下方字幕「不能把任務丟給它就預設它會生出你腦子裡那個完美的版本」">

他給的類比是帶新同事：先給它背景，講清楚目標，看一下它的計畫，最後驗收它的成果。這四步對應到前面章節講的東西，給背景是上下文，看計畫是動手前先確認方向，驗收則是你自己要花的那幾分鐘。

它做錯的時候，不要只丟一句「我不喜歡，重做」。**要告訴它哪裡不對、為什麼不對、下次遇到類似情況該怎麼判斷。**

Gary 說你越是這樣帶它，它就越像一個真的懂你做事方式的夥伴，不會每次都從零開始亂猜。這樣用下去，Codex 就不只是幫你省幾分鐘，它會慢慢變成一套你可以不斷訓練、不斷校正、不斷沉澱的工作系統。

影片這段結尾，Gary 也提到他另外寫了一篇完整的 Codex Playbook，連結放在他的影片資訊欄。

## 新手先做這五件事（影片 16:47）

最後 Gary 快速做了一個總結。他的開場是：如果你是新手，先不要被 Codex 的所有功能嚇到，掌握幾件事就好。

<img src="/images/blog/codex-beginner-guide/shot_1012s.jpg" alt="投影片標題「新手，掌握這五件事」，畫面下方字幕只有「第一」兩個字">

第一，記住 Codex 是一個能進到你工作環境、直接動你檔案的 AI Agent。

這是它跟網頁版聊天機器人最根本的差別。它不是在對話框裡給你答案，它是實際去改你電腦裡那份檔案。這個認知決定了你後面所有的用法，也決定了為什麼權限那關要謹慎。

第二，先把那四個基本功搞懂：專案、權限、上下文，還有 AGENTS.md。

<img src="/images/blog/codex-beginner-guide/shot_1021s.jpg" alt="投影片「新手，掌握這五件事」列出前兩項，1 是「能動你檔案的 AI Agent」，2 是「四個基本功：專案／權限／上下文／AGENTS」，下方字幕「專案，權限，上下文，還有 AGENTS markdown」">

Gary 說這是駕馭任何 agentic 工具最基本的東西，不管你用的是 Claude Code 還是 Codex 都要會。換句話說，這四樣學起來不會綁死在某個工具上，之後換工具也帶得走。

第三，開始拿它處理本地文件、表格、網頁、郵件、簡報，這些最容易有感的日常任務。

<img src="/images/blog/codex-beginner-guide/shot_1030s.jpg" alt="同一張「新手，掌握這五件事」投影片列到第三項「拿它處理本地日常」，底下標注文件／表格／網頁／郵件／簡報">

順序上他把日常任務排在自訂功能前面，理由就是「最容易有感」。先讓自己相信這東西真的省時間，再談進階。

第四，等你用順了，再學著搭自己的 Skills、串常用的外掛程式，把每天要做的雜事交給自動化排程。

第五，記住它不只是你的助理跟執行夥伴，也是你的家教。用 Gary 的原話收尾：你會的事情可以叫它做，不會的事情可以先叫它教你，學會了再叫它幫你做。
