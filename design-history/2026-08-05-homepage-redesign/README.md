## 00-live-before — 現行線上首頁

**一句話定位**：Tailwind 出廠配色，看起來像框架預設值，沒有記憶點。

**色票**：底色 `#f7fbff`、重點色 `#1688e8`。全站 `src/` 內 `sky-*` 系 class 共 71 處、硬編 `#1688e8` 共 39 處（其中 1 處是 `global.css:41` 的中文註解說明用色策略，不是實際渲染的樣式，扣除後**實際硬編樣式 38 處**）。卡片一律 `rounded-[1.75rem]` 圓角。首頁共七個區塊。

**字級**：H1 用 Tailwind `text-2xl`（手機 24px）→ `md:text-5xl`（桌面 48px，即 `3rem`），`leading-snug`。

**這版想解決什麼問題**：這不是一個「原型」，是現況基準版，用來對照其他四版的差異。

**為什麼被選／被否**：不適用——這是被改版的對象，不是候選方案。問題本身就是動機：配色、圓角、字級全部是 Tailwind 出廠值，訪客看不出這是誰的網站。

**這份快照的限制**：`index.html` 是用瀏覽器載入 `https://aixwang.dev/` 後、以 `page.content()` 存下渲染後的完整 DOM，**不是**原始原始碼，也不是離線可用的封存——頁面唯一外部依賴的樣式表 `/_astro/about.BV9tlBwv.css` 仍以站上絕對路徑引用，日後該站重新部署、檔名雜湊改變後，這份 `index.html` 的樣式會失效（只剩 HTML 結構）。截圖（PNG/JPG）不受此限制，永遠保留當下的真實畫面。

## 01-variant-a-mdfile — 「.md 檔案感」

**一句話定位**：把首頁做成一份看起來像原始 Markdown 檔案的頁面。

**色票**：石榴紅 `--accent:#8A2B3C`；底色 `--paper:#F7F7F4`；文字 `--ink:#1A1917`。

**字級**：H1 `font-size:clamp(1.72rem, 1.14rem + 2.5vw, 2.85rem)`，在 1440px 桌面視窗下觸頂，實際渲染 **45.6px（2.85rem）**。等寬字體 IBM Plex Mono 用於 frontmatter 與標籤，`##` 前綴、零圓角（`border-radius:0`，唯一例外是幾個 999px 的膠囊按鈕與 2px 的極小圓角裝飾）。

**這版想解決什麼問題**：測試「開發者美學」——用 `.md` 檔案的視覺語言（YAML frontmatter、`#` 標題前綴）強化「這是工程師寫的內容，可信」的訊號。

**被否原因**：目標讀者是「不會程式、會用 AI 對話的人」，但這版進站第一眼是五行 `key: value` 的 frontmatter（`author:` `role:` `updated:` `tags:`），要往下捲才輪到第一句人話。導覽列是 `/blog` `/one-on-one` `/speaking` `/faq` `/about` 這種路徑式命名，同樣是工程師會讀的語彙。而且**這版一張圖都沒有**——現行首頁有 3 個影片嵌入、4 張演講照、8 個工具 logo，這版全部拿掉，只剩文字與等寬字排版。這個方向自評「為錯的讀者最佳化」：它服務的是懂 Markdown、覺得 frontmatter 很親切的人，但目標客群恰好是那些「不會程式」才需要教學的人。

## 02-variant-b-dialogue — 「對話版式」（被選為方向）

**一句話定位**：把首頁排成一次真實的問答對話，提問用襯線體、回答用無襯線體區分角色。

**色票**：暖紙色 `--paper:#F7F5F1`；暗酒紅 `--accent:#7A2E3B`。色相刻意選在 **350°**，避開幾個常見 AI 品牌與框架的色相：Claude 17°、Meta／Gemini 217°、ChatGPT 165°，以及 Tailwind 出廠藍（本站現行首頁的 `#1688e8`）。

**字級**：提問用襯線體、回答用無襯線體的版式規則；首屏大標 `.turn--hero .ask-q { font-size:clamp(27px, 6.6vw, 46px) }`，1440px 桌面視窗下觸頂，實際渲染 **46px**。

**這版想解決什麼問題**：現行首頁與方向 A 都是「單向陳述」版式（我方講、讀者聽）。這版把版式本身改成「一問一答」的結構，直接模擬目標讀者最熟悉的互動形式——跟 AI 對話。

**為什麼被選**：四個變體裡，**唯一一個「版式本身就在說目標讀者語言」的變體**——不是靠文案說「你可以問我問題」，而是整個頁面結構就是問答本身。缺陷同樣具體：服務入口（找我合作／軟體開發接案／一對一教學等連結）距離頁首 **4,451px**，讀者要捲很長一段才會看到轉換點。這個缺陷在 B-v3 沒有修，被留到「這一輪學到什麼」的結論裡一起討論。

## 03-variant-b3-bigtype — B 的字級放大版

**一句話定位**：只改一個變數的對照實驗——把 B 版的首屏 H1 字級大幅放大，其餘版式、色票、間距全部不動。

**色票**：與 02-variant-b-dialogue 完全相同（`--paper:#F7F5F1`、`--accent:#7A2E3B`）——這版刻意不碰色票，才能單獨驗證字級的效果。

**字級**：首屏大標 `.turn--hero .ask-q { font-size:clamp(56px, 8vw, 96px) }`，1440px 桌面視窗下觸頂，實際渲染 **96px**（對照 B-v2 的 46px，桌面首屏 H1:內文字級比從 2.88× 拉高到 6.0×）。

**這版想解決什麼問題**：驗證一個假設——「客戶喜歡 jisto.tw 的大器感，來自它極端的字級對比（大標題 vs. 小內文）」。做法是只調 H1 一個變數，看首屏觀感是否因此接近 jisto。

**結果：假設只對一半。** 首屏確實變得更像 jisto——字級對比拉開後視覺重量明顯不同。但實測 jisto.tw 的 CSS 後發現，它的 display 級大字**不是只出現在首屏**，頁面中段也重複出現同等級的大字（`.j-projects-showcase__headline h2` 用 `clamp(48px,5.7vw,96px)`、`.j-nube-case-card__label` 用 `clamp(52px,8vw,98px)`），而且 jisto 的內文字級只有 13–14px，對比感是**整頁一致的字級策略**，不是首屏獨有的裝飾。B-v3 只把 hero 的一顆大字放大，頁面其他地方的字級沒有跟著調整策略，等於只複製了 jisto 效果的一半。

## 04-variant-c-gallery — 直接套用 jisto.tw 色票的極簡版

**一句話定位**：零彩色，直接沿用 jisto.tw 實測到的色票與排版工藝細節。

**色票**：底色 `--paper:#f3f2ed`；文字 `--ink:#08090a`；髮絲分隔線 `rgba(8,9,10,.14)`。全頁沒有任何彩色（accent hue）。

**字級**：`.display { font-size:var(--fs-display) }`，`--fs-display:clamp(56px, 10vw, 140px)`，1440px 桌面視窗下 10vw=144px 已超過上限，實際渲染觸頂於 **140px**——四個變體裡字級最大的一版。

**這版想解決什麼問題**：把 jisto.tw 實測到的視覺系統（色票、字級尺度、間距）直接搬過來套用在自己的內容上，看整體觀感。

**被否原因**：那是複製，不是設計。拿這版去給客戶看，等於在展示「我能重做別人的網站」，不是「我理解你的品牌該長什麼樣子」。但這版拆解 jisto 版式時歸納出的**八條排版工藝標準**（字級尺度、間距節奏、髮絲線規則等）被吸收進 B-v2／B-v3 的實作細節裡，不是整套白費——只是配色與「零彩色」這個決策本身不能直接用。

## 這一輪學到什麼

> 首頁的「乾淨」不是字級問題，是資訊量問題。實測 B-v3 有 58 個可點連結、19 個標題、3,694 字；jisto 首頁預渲染版只有 7 個連結、82 字，細節全藏在點開的抽屜裡。字放到 96px 也救不了資訊過載。

這個結論解釋了為什麼 B-v3（96px 大字）在視覺上更接近 jisto，但整體「乾淨感」仍然沒有追上——因為兩者要解決的不是同一個問題。B-v3 動的是字級這個表層變數，jisto 的乾淨感來自資訊架構本身：大量細節被折進點開才看得到的抽屜元件，首頁預渲染出來的內容量因此壓到極低。放大字級不會減少頁面上的連結數、標題數、字數，所以「資訊過載」的根因沒有被 B-v3 觸碰到。後續如果要繼續往「乾淨」這個方向走，該調的變數是資訊架構（哪些內容摺疊、哪些留在首頁），不是再把字級往上加。
